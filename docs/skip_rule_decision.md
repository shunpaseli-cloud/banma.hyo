# 見送りルール本番投入の判断材料

作成日: 2026-11-01（Asia/Tokyo）  
対象: 時系列学習 λ=0.92・軸1頭＋相手2〜4位の3連複3点  
検証分割: 前半458R（〜2026-08-02 9R）／後半458R（同日10R〜10-31）  
根拠ファイル: `/tmp/skip_rule_split.json`, `/tmp/miss_analysis.json`, `/tmp/half_split_tune.json`  
**本番コードは本レポート作成時点では変更していない。**

## 1. 候補ルールと影響

| ルール | 前半 購入R / 的中率 | 後半 購入R / 的中率 | 後半で見送った的中 |
|---|---|---|---|
| 見送りなし | 458 / 12.23%（56） | 458 / **11.79%（54）** | — |
| 頭数≥10のみ見送り | 221 / 15.38%（34） | 149 / **14.77%（22）** | 54−22=**32件**（309R見送り中） |
| **採用候補: 頭数≥10 または スコア1位−5位&lt;0.05** | 156 / 16.67%（26） | 126 / **15.87%（20）** | 54−20=**34件**（332R見送り中） |

- データ上の最大頭数は10のため、「≥10」は実質 **ちょうど10頭立て**。
- 的中率は上がるが、購入レースは後半で **458→149（約32%）** または **458→126（約28%）** に減る。
- 見送りで取りこぼす的中が後半だけで **32〜34件**ある（ベースライン54的中のうち過半）。
- 3連複払戻32Rはすべて後半・かつ 10/25・10/26・10/31 のみ（元JSONの紐づけ制約）。頭数見送りを入れると、払戻サンプル上の購入Rもさらに減り、**回収率判断は現状よりさらに不安定**。

## 2. 安定性（前半選定 → 後半再現）

- **頭数≥10見送り:** 前半 +3.2pt → 後半 +3.0pt。方向・幅とも再現。
- **頭数≥10 OR スコア差&lt;0.05:** 前半で選定（購入≥30%制約下の最高的中）。後半も +4.1pt で再現。
- **スコア差のみ**（例: 1位−2位&lt;0.05）: 前半20.7% → 後半9.3%で**崩れ**。単独では不安定。
- 重み係数の再調整（過去着順×2等）は同じ分割で後半効果が消えたが、**頭数見送りは後半でも残った**点が対照的。

## 3. 本番反映する場合の実装方針（未実装・提案のみ）

1. **予測側（推奨）**  
   - `frontend/src/learnScore.js`（または RaceCard 表示直前）で `entries.length >= 10` を判定。  
   - UI: 「見送り（10頭立て）」バッジ／3連複・三連単ブロックを非表示または薄表示。  
   - スコア計算自体は動かして詳細分析は残してもよい。
2. **買い目生成**  
   - `trio.js` / `trifecta3()` 呼び出し前にガード。見送り時は空配列＋理由コード。
3. **学習スクリプト**  
   - `frontend/scripts/train_learned_model.mjs` は学習対象を変えなくてよい（見送りは運用フィルタ）。  
   - 旧 `ban_ei_feedback.py` は現行SPAでは主経路ではない。入れるなら同様に field ガード。
4. **設定**  
   - `frontend/src/data/skip_rules.json` に `{ "min_field_skip": 10, "min_score_spread": 0.05 }` を置き、ON/OFF可能に。
5. **入れるなら段階導入**  
   - まず「頭数≥10のみ」（単純・再現済）。スコア差条件は任意オプション。

## 4. 判断

| 観点 | 評価 |
|---|---|
| 的中率 | 後半で +3〜4pt。再現あり |
| 機会損失 | 後半的中の過半を見送りで逃す |
| 回収率 | 払戻32R偏在のため、見送り後のROIは信頼できない |
| 実装コスト | 小（表示ガード中心） |
| 過学習リスク | 頭数ルールは低め。複合スコア差は要オプション扱い |

**推奨:**  
- **本番に「頭数10見送り」を入れる判断は可能**（分割検証で再現）。ただし目的が「的中率％の向上」なら妥当、「的中件数・回収の最大化」なら見送りによる取りこぼしが大きく、**入れない／弱め（表示のみ警告）が無難**。  
- スコア差条件付きルールは効果は出ているが、購入Rがさらに減るため、**デフォルトOFFの実験フラグ**がよい。  
- 払戻の日付付き再紐づけ後に、見送りあり/なしのROIを再評価してから強くONにするのが安全。
